**Що я реалізував (1–2 речення):**
Налаштував базову архітектуру для MedBook API (Fastify + Drizzle ORM) зі строгим конвеєром перевірки якості коду (ESLint, Prettier, Husky). Створив власні стандарти (`DoD`, `MADR`), специфікацію (`spec.md`) та впровадив `git-hooks`, які успішно блокують коміти з невалідною конфігурацією.

**Топ-3, де я «зрізав кути» / знайшов і виправив (проти spec):**

1. **Відсутній `.gitignore`:** ШІ згенерував структуру проєкту, але забув про `.gitignore`, що призвело б до коміту папки `node_modules` (сміття в репозиторії). Я провів аудит, додав правильний `.gitignore` для Node.js і вилучив `node_modules` з кешу Git до створення коміту.
2. **Помилка компіляції TypeScript (відсутній вхідний файл):** ШІ запропонував хук `make test-smoke` (через `tsc --noEmit`), але не створив жодного `.ts` файлу. Компілятор падав із помилкою "No inputs were found". Я самостійно створив `src/index.ts`, щоб збірка і перевірка типів проходили успішно.
3. **Відсутня залежність для лінтера (заблоковано хуком):** ШІ надав `eslint.config.mjs` із використанням `@eslint/js`, але не додав цей пакет у залежності. Мій налаштований `git-hook` успішно відловив цю помилку та заблокував мій коміт. Я встановив бракуючий пакет, після чого конвеєр запрацював.

**Ключове рішення — які альтернативи зважив і чому обрав цю (ADR):**
Замість стандартної зв'язки Express + Prisma, я обрав **Fastify + Drizzle ORM**. Альтернативи: NestJS (занадто важкий для старту) та TypeORM. Fastify забезпечує високу продуктивність і має вбудовану валідацію схем (Ajv). Drizzle ORM обрано через сувору типізацію та відсутність прихованого бінарного рушія (на відміну від Prisma, з якою були проблеми). Деталі у `docs/adr/0001-stack-selection.md`.

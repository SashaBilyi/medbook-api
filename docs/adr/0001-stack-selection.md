# ADR 0001: Вибір Web-фреймворку та ORM

**Контекст та проблема:**
Для старту проєкту необхідно обрати базовий фреймворк для HTTP-сервера та інструмент для роботи з базою даних.

- _Обмеження 1:_ Використання Express не схвалюється як застарілий підхід без вбудованих сучасних механізмів (напр. валідації).
- _Обмеження 2:_ Негативний досвід роботи з Prisma ORM (проблеми з бінарним рушієм `query-engine`).

**Розглянуті альтернативи:**

- _Web-фреймворк:_ NestJS (надлишковий для цього масштабу), Koa, Fastify.
- _ORM:_ TypeORM (важкий, застарілий підхід до декораторів), Sequelize, Drizzle ORM.

**Рішення:**

1. **Фреймворк: Fastify.** Обрано через високу продуктивність, архітектуру плагінів та вбудовану валідацію JSON-схем (Ajv), що гарантує суворий контроль вхідних даних на рівні роутів "з коробки".
2. **ORM: Drizzle ORM.** Обрано через строгу типізацію (type-safe), генерацію прозорого та зрозумілого SQL і відсутність прихованих фонових процесів (як у Prisma).

**Наслідки:**

- Досягається вища продуктивність і стабільність у порівнянні зі зв'язкою Express + Prisma.
- Потребує написання схем валідації у форматі JSON Schema для Fastify.
- Дає повний контроль над міграціями бази даних у чистому SQL через Drizzle Kit.
